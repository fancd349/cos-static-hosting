## 腾讯云COS静态托管能做什么，不能做什么

COS 静态托管适合放纯静态内容，不适合运行需要服务端计算的程序。判断标准不复杂：文件上传后内容不再变化，就适合；需要根据用户请求查数据库、动态生成页面，就不适合。

能放的东西包括：

- 个人主页、博客、产品落地页
- 项目文档站，比如 VitePress、Docusaurus 打包出来的产物
- Vue、React 等前端框架构建后的 dist 目录
- 图片、字体、视频等静态资源

不能做的事同样明确：

- 不支持 PHP、JSP、ASP.NET 这类服务端脚本，官方文档的建议是需要动态网站时改用云服务器 CVM
- 不能处理登录注册、支付回调、数据库查询这些后端逻辑
- 静态网站的访问节点只支持 GET/HEAD Object 操作，POST 请求这类需求得另想办法
- 访问节点区分英文大小写，配置文件名时要注意

COS 本身还兼容 S3 API，提供控制台、多种语言 SDK 和命令行工具。图片裁剪、水印、转码这些处理可以交给数据万象，通过 URL 参数完成，不必另外搭一套图片服务。

## 从零到上线：七步配置流程

整个流程拆成七步，顺利的话半小时能跑通。真正卡人的通常不是 COS 本身，而是域名解析和备案。

1. 完成实名认证并开通 COS。没实名认证用不了这个服务。
2. 创建存储桶。名称只能用小写字母和数字；地域选离目标用户近的；公开站点把访问权限设为公有读私有写。
3. 上传网站文件。`index.html` 放根目录；有子目录的，每个目录层级都放一个 `index.html`。
4. 开启静态网站。路径是基础配置 > 静态网站 > 编辑，当前状态设为开启，索引文档填 `index.html`。
5. 绑定自定义域名。进入域名与传输管理 > 自定义源站域名 > 添加域名，源站类型必须选静态网站源站。然后去 DNS 服务商添加 CNAME 记录。
6. 配置 HTTPS。给自定义域名绑定证书。
7. 验证。分别访问根域名、子目录地址和一个不存在的地址，确认返回首页、子目录索引和 404 页面。

几个配置项的具体作用：

| 配置项 | 建议填写 | 说明 |
| --- | --- | --- |
| 索引文档 | index.html | 访问根目录或子目录时返回的首页；没有 index.html 会找 index.htm，再没有就 404 |
| 错误文档 | 404.html（可选） | 每个存储桶只能配一个，可以放在子目录下，但不能按子目录分别配置 |
| 错误文档响应码 | 原始错误码或 200 | 单页应用要选 200，后文会讲 |
| 强制 HTTPS | 证书配好后再开 | 自定义域名证书异常时会跳回默认域名 |
| 忽略 html 扩展名 | 按需 | 访问 /index 时自动匹配 index.html |
| 重定向规则 | 按需 | 支持 4xx 错误码和前缀匹配，不支持通配符 |

## 五个最容易踩的坑

最常见的坑是默认域名不渲染页面、直接下载文件；其次是自定义域名的源站类型选错，导致静态网站规则完全不生效。下面这几条按踩坑概率排序。

1. **2024 年后新建的桶，默认域名会直接下载文件。** `cos.ap-xxx.myqcloud.com` 和 `cos-website.ap-xxx.myqcloud.com` 都属于官方说的“默认域名”。新桶用它们访问 `index.html`，浏览器会弹出下载框。解决办法是绑定自定义域名，源站类型选静态网站源站，之后一律用自定义域名访问。

2. **源站类型选成了默认源站。** 添加自定义域名时如果选“默认源站”，COS 只当普通对象存储回源，不会执行索引文档、错误文档这些规则。表现是访问根目录不会自动返回首页，排版和跳转全乱。

3. **子目录里没放索引文档。** COS 对以 `/` 结尾的地址会找该目录下的 `index.html`，其次 `index.htm`，都没有就返回 404。博客按年份分目录、文档站按章节分目录的，每一层都要补上索引文件。

4. **文件名大小写对不上。** 访问节点区分大小写，Windows 本地不区分。`Index.html` 和 `index.html` 在桶里是两个不同的对象，配置里写错一个字母就是 404。

5. **重定向规则和错误文档的边界没弄清。** 重定向规则不支持通配符，想同时处理 `index1/`、`index2/` 得分别建规则；错误文档一个桶只能配一个，想给不同子目录配不同错误页做不到。

还有一个组合型故障值得单独提：自定义域名开了强制 HTTPS，但证书没配好。官方文档说明，这种情况会跳回默认域名，而默认域名又会触发下载。表面看是“HTTPS 打不开”，实际是证书和默认域名两个问题叠在一起。

## 公开站点和内部站点，权限怎么设

对外公开的站点用公有读私有写；不想让所有人访问的，用私有读写，再通过 CDN 回源鉴权和 CDN 鉴权控制访问。

公有读私有写配置最省事，任何人拿到 URL 就能访问。风险是资源可能被盗用、被刷流量，官方文档的建议是参考防盗刷指引，配置 Referer 防盗链和用量告警。

私有读写的桶直接访问会返回 403，静态网站也要通过 CDN 回源鉴权、CDN 鉴权做全链路保护。内部文档、预览环境、还没上线的项目适合这种模式。

访问权限在权限管理 > 存储桶访问权限里修改，和静态网站开关在两个地方，配置时别只开了一个就以为完事。

## Vue/React 单页应用：把 404 交回给 index.html

把错误文档设置为 `index.html`，并把错误文档响应码设为 200，Vue 或 React 的前端路由就能正常工作。

原理不复杂：用户访问 `/user/123`，桶里没有这个文件，COS 默认返回 404；配置之后，它返回 `index.html` 的内容加 200 状态码，前端 router 读到路径后渲染对应页面。官方文档明确写了错误文档响应码可以配置为原始错误码或者 200，这是 SPA 托管的标准做法。

代价是所有不存在的地址都会返回首页，真正的死链也会显示首页内容。对 SEO 有要求的站点，最好同时准备 sitemap，并在页面里加 canonical，让搜索引擎知道哪个是主版本。

另一条路是用重定向规则做前缀匹配，但前缀要单独建规则、不支持通配符，路由多的项目配起来很啰嗦，不如错误文档直接。

## 什么情况下不该用 COS 静态托管

需要服务端逻辑，或者完全不想碰备案的，COS 静态托管不是最优解。

- **需要登录、支付、数据库、接口**：用 CVM 部署后端，或者云函数加 API 网关，COS 只放前端静态资源。
- **面向国内用户但不想备案**：可以选香港等境外地域的存储桶，绑定自定义域名通常不需要备案，但访问速度和网络稳定性要自己权衡。
- **只是练手 demo、不要求国内访问**：GitHub Pages、Cloudflare Pages 这类海外静态托管有免费档，也不用备案，推代码就能发布。缺点是国内访问不稳定，商业项目还要看平台条款。

COS 的优势在于和腾讯云 CDN、数据万象、云函数在同一套体系里。域名备案一次，后面加图片处理、加后端接口都顺，不用在几个平台之间来回搬。

## 常见问题

**腾讯云COS静态托管需要买服务器吗？**
不需要。COS 本身就是存储服务，静态网站功能直接对外提供访问，不经过你的服务器。

**一定要备案吗？**
国内地域的存储桶绑定自定义域名，域名需要完成 ICP 备案；香港等境外地域通常不需要。用默认域名不涉及备案，但 2024 年后新建的桶用默认域名会直接下载文件。

**支持 HTTPS 吗？**
支持。给自定义域名绑定证书即可，静态网站设置里还有强制 HTTPS 开关。证书没配好时别开强制 HTTPS，否则自定义域名可能跳回默认域名。

**能放视频吗？**
能。但视频消耗的是流量，不是容量，流量费通常比存储费更显眼。建议开 CDN、配防盗链，别把桶直接当公开视频源。

**更新文件后访问的还是旧内容？**
先看是不是 CDN 缓存。CDN 有缓存时间，刷新缓存后再看；浏览器本地缓存也会造成同样现象。

**一个存储桶能放几个网站？**
一个桶只有一套静态网站配置：一个索引文档、一个错误文档、一套重定向规则。多个独立站点建议开多个桶，或者放在不同目录下共用一套规则。
